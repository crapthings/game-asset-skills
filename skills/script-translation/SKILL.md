# 剧本翻译

按下列三个阶段完成工作。所有交付路径相对用户目标项目根目录，不写入本技能安装目录。读取目标项目的 `AGENTS.md`，已有成果先检查再续做，不覆盖不相关文件。

## 阶段 1：获取原文与初译

1. 从用户提供的剧本链接获取完整正文。链接缺失时询问；网页含分页、章节或附件时逐一获取并核对顺序。遇到登录限制、缺页或无法读取的内容，明确说明缺口并请求可访问来源，不把摘要或部分正文当作完整剧本。
2. 将完整英文正文保存为 UTF-8 的 `references/原文.txt`。保留标题、场次、人物名、对白、舞台指示及原有顺序，去除导航、广告等非正文；PDF/OCR 提取后检查断行、错序、漏页和字符错误。来源 URL、版本及完整性核对情况记入 `references/审校记录.txt`，与正文分开。
3. 通读原文，理解人物关系、时代背景、伏笔、指代和语境，再按场次或稳定段落分批翻译。建立原文位置与译文位置的对应关系，跨批次延续人物称谓、术语和语气，不以总结代替翻译。
4. 将初译保存为 UTF-8 的 `references/译文.txt`。表达符合自然中文，避免逐词硬译；保留原著情节、因果、信息揭示顺序、人物立场、情绪、潜台词及语气强度。不得擅自增删剧情、解释伏笔、改写人物动机，或为通顺而省略对白与舞台指示。双关、文化意涵或歧义无法直接保留时，在审校记录中说明处理与待核事项，不把译者推测混进正文。

## 阶段 2：审校与定稿

按顺序执行，每轮以完整原文为依据，不只检查译文。长剧本逐段完成并记录覆盖范围；所有轮次完成前保持“初译／审校中”状态。

| 环节 | 执行要求 | 核心检查 |
| --- | --- | --- |
| 译者自校 | 对照原文通读译文，修正错译、漏译、不通顺表达 | 准确性 |
| 交叉审校 | 由第二位语言专家独立逐段核对原文与译文，标明问题位置、依据与修改建议 | 忠实度、完整性 |
| 语言润色 | 在不改变含义的前提下调整句式、衔接、用词和人物语气 | 流畅性、可读性 |
| 术语统一 | 全文核对人名、地名、称谓、专业术语及固定译法，保留剧情需要的有意差异 | 一致性 |
| QA 检查 | 核对数字、日期、单位、否定、数量关系、说话人、标点、格式、段落顺序与遗漏 | 技术性错误 |
| 终审定稿 | 依据原文处理审校意见和争议，复核修改涉及的上下文，确认全文质量 | 整体质量 |

- 交叉审校应使用独立的第二位语言审校者；环境支持多代理时，委派独立审校代理，提供完整原文、译文和位置索引，要求逐段核对并返回覆盖范围与问题。长文可分批交给同一审校者，直到覆盖全文。
- 无法取得独立审校者时，可继续其余环节，但在记录和交付中明确“交叉审校未完成”，不可把同一译者的再次自检声称为独立审校，也不可宣称全部终审通过。
- 将术语表、逐轮覆盖范围、实质问题、修改结果、争议处理依据与未解决事项集中记录在 `references/审校记录.txt`。术语表包含原文、统一译法、必要的语境说明。
- 各轮修订回写 `references/译文.txt`。终审后该文件为最终译文；仍有缺文、未完成审校或影响理解的歧义时，清楚标注状态与具体位置。

## 阶段 3：分章与清单

依据定稿译文并回查原文，不凭常识补充原著未出现的角色、场景或道具。“出境”按“出场”理解；区分实际出场与仅被提及。

### 自然叙事断点分章

- 使用 Natural Narrative Break（自然叙事断点）：优先在一段行动或冲突收束、目标或视角转换、显著时间跳跃、地点转移或新事件启动处划分。不得机械按字数切割，也不要截断连续对白、动作或紧密的因果链。
- 保留原著已有幕／场标记；新章是整理层，不改写或重排剧情。给 `references/译文.txt` 添加明确的章节编号和简洁章名，保持正文完整，不重复或遗漏段落。
- 将章号、章名、起止原文位置、起止译文位置及断点理由保存到 `references/章节清单.txt`，供清单溯源。位置可用原幕／场／段落编号与短句锚点，完成后确认边界仍可定位。

### 角色清单：`references/角色清单.txt`

- 按主角、配角、群演分类。主角推动核心叙事；配角有独立身份或明确剧情作用；群演为无独立身份的背景人群。依据全剧功能分类，不仅依据台词多少；边界不明时说明判断依据。
- 每项包含稳定编号、中文名／原文名、别名或称谓、类别、原文明确的身份与关系、首次出场及相关章节／场次。合并同一角色的别名，区分同名不同人。
- 保留有演出作用的旁白、画外音、非人角色及群体，标注出场方式；仅被提及者另列“仅提及”，不混入实际出场名单。不要推断外貌或服饰。

### 场景清单：`references/场景清单.txt`

- 按地点分组，列出地点下实际出现的具体场景／子空间，统一同一地点的不同称呼。
- 每项包含稳定编号、地点、场景名／原文名、内外景、原文明确的时间或状态变化、相关章节／场次。未知信息标为未说明；回忆、梦境等标注叙事层次；仅提及地点另列。
- 区分地点本身与同一地点的昼夜、天气、损毁等状态，避免把每次出场都重复建为新地点。

### 道具清单：`references/道具清单.txt`

- 提取影响行动、线索、冲突、人物识别或演出交互的重要物件与道具，避免无差别罗列所有背景摆设。
- 每项包含稳定编号、中文名／原文名、剧情用途、持有者或关联角色／场景、原文明确的重要状态变化、相关章节／场次。区分同类物件与剧情中的同一件物品；用途不确定时标注，不添加设计。

## 交付核对

交付前确认原文完整、译文逐段覆盖，分章前后正文没有丢失或重复，清单名称与译文及术语表一致，所有条目都有可定位依据。报告七个输出文件的路径、审校状态及具体未解决项：原文、译文、审校记录、章节清单、角色清单、场景清单、道具清单。需要继续资产分析时，可将定稿剧本和清单交给 `asset-analysis`；本技能不自动生成图片或改编剧情。
